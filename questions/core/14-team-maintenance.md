# Core Team and Maintenance

1. Who owns and maintains the system in six months?
2. Can a new engineer run and change it using only repository documentation?
3. Which non-obvious decision, dependency, or manual step creates the largest bus-factor risk?
4. Are contracts, architectural decisions, compatibility, and deprecation paths recorded?
5. Which dependencies or deliberate shortcuts are likely to age badly?
6. What review, incident, release, and support process keeps it healthy?

Verify clean setup, documentation handoff, dependency health, change blast radius, and ownership of credentials and operations.
